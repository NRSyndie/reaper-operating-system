## Context

### What Bootinfo v1 Looks Like Today

The current `bootinfo_t` struct (in both `kernel/include/bootinfo.h` and `shared/include/bootinfo.h`) is:

```c
typedef struct boot_info {
    uint64_t magic;
    uint64_t version;
    uint64_t hhdm_offset;
    uint64_t genesis_cap_slot;
    uint64_t memmap_base;
    uint64_t memmap_count;
    uint64_t kernel_phys_start;
    uint64_t kernel_phys_end;
    uint64_t reserved[8];
} boot_info_t;
```

**Key properties:**
- Magic is `0x5245415045524F53` (`"REAPEROS"`)
- Version is currently `1`
- The struct is exactly 128 bytes (8 × 8 = 64 bytes for the first 8 fields, + 64 bytes for reserved)
- Paradigm reads it at virtual address `0x1000`
- Paradigm checks: magic, version == 1, genesis_cap_slot == 1, kernel_end > kernel_start

### What We Need Bootinfo v2 to Add

**Requirements:**
1. Preserve all existing fields at their current offsets (ABI compatibility)
2. Bump `BOOTINFO_VERSION` from 1 to 2
3. Add a module table — an array of descriptors, each containing:
   - Module index
   - Physical base address
   - Size in bytes
   - ELF entry point (if applicable)
   - Module type (explicit, not order-dependent)
   - Module flags
   - BLAKE3 hash of module content
   - Module name (optional, for debugging)
4. Add framebuffer metadata:
   - Physical base address
   - Width
   - Height
   - Pitch
   - Pixel format
   - A presence flag (framebuffer is optional)
5. Add an integrity field — BLAKE3 hash of the struct itself (excluding this field)
6. Add a flags field (for presence flags, future expansion)

**Key design decisions from our planning:**
- Fixed-size module table with 16 entries
- Module type is explicit (not order-dependent)
- Framebuffer metadata is optional (absence is not a failure)
- No `packed` attribute; use natural alignment and verify with static assertions
- Static assertions go in dedicated verification files, not in the shared header

### Constraints
- All existing fields must remain at the same offsets
- The struct must remain naturally aligned (no `packed`)
- Both `kernel/include/bootinfo.h` and `shared/include/bootinfo.h` must be identical
- The header should be clean and focused on the interface (no static assertions)
