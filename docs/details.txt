What Changed and What It Means
The biggest structural change — Paradigm's role

In the original document, Paradigm was described as the "first god" that uses GENESIS_CAP to construct reality. It was simultaneously the bootstrapper AND the ongoing Reality orchestrator AND the security authority.

In our new design, we split that cleanly:

Genesis takes the bootstrapper role — it holds GENESIS_CAP, constructs the environment, and exits
Paradigm becomes purely the ongoing Reality and Security daemon
This is actually a significant improvement over the original. The original Paradigm was doing too much. A single entity that both bootstraps the system AND enforces ongoing security is a larger attack surface than two entities with distinct, bounded responsibilities.

What this means for the document: The boot philosophy section needs updating. "Paradigm is thus the first god" is no longer accurate. Genesis is the first god — brief, purposeful, and self-terminating. Paradigm is the ongoing sovereign.

The most significant absorptions worth thinking through

Cipher absorbed into Sage

The original Cipher owned process lifecycle, namespaces, per-app sandboxes, and per-reality UID/GID. The original Sage owned memory policy. In the new design, Sage owns process AND execution, which covers what both Cipher and the original Sage were doing.

This is clean because process management and execution policy are deeply coupled — you can't meaningfully separate "what process is running" from "what memory and scheduling policy applies to it." Merging them removes an artificial boundary.

Sentinel absorbed into Paradigm

The original Sentinel was the watchdog — monitoring, forensic logging, threat scoring, anomaly detection. In the new design, all of that lives inside Paradigm's security domain.

This makes sense architecturally because monitoring and enforcement are two sides of the same coin. Sentinel detected threats and could "recommend or force migration to different realities" — but that recommendation had to go through Paradigm anyway. Removing the intermediary is cleaner.

However — this is worth a second look. The original document was careful to say Sentinel could escalate independently of Paradigm. That independence was a security feature — if Paradigm itself was compromised, Sentinel could still detect and respond. By absorbing Sentinel into Paradigm, you lose that independence.

The question this raises: Should monitoring and audit live inside Paradigm, or should they be a separate system daemon child of Paradigm that maintains some degree of independence? Not a full separate core daemon — but perhaps an internal separation within Paradigm's domain where the audit and monitoring subsystem has its own capability scope that even Paradigm's other subsystems can't tamper with.

What Semi-Independent Audit Means in Practice
Within Paradigm's domain, the audit subsystem operates under a specific set of constraints that isolate it from Paradigm's other logic:

Capability isolation

The audit subsystem holds its own audit write capability — a capability that Paradigm's core logic cannot revoke, modify, or suppress. Even if Paradigm's Reality control logic has a bug or is actively compromised, it cannot silence the audit trail because it doesn't hold the audit capability. The audit subsystem holds it directly, derived from Genesis during bootstrap, not from Paradigm's ongoing authority.

This means the chain of custody for the audit capability looks like:

Genesis mints audit capability
    ↓
Genesis transfers it directly to the audit subsystem
    ↓
Paradigm's core logic never touches it
    ↓
Audit subsystem holds it independently for the
lifetime of the system
Memory isolation

The Fate String ring buffer and the audit lattice live in memory regions that only the audit subsystem can write to. Paradigm's other subsystems can read audit records — they need to for forensic queries — but they cannot write to the audit chain directly. Only the audit subsystem writes.

Behavioral independence

The audit subsystem has its own response logic. If it detects anomalous patterns — including anomalous behavior from Paradigm's own subsystems — it can:

Flag the anomaly in the Fate String chain
Escalate to a pre-defined recovery path
In extreme cases, trigger a controlled system halt independently of Paradigm's decision
This is the preserved Sentinel property. The watchdog can bark even if the handler is compromised.
